# 航班日期弹窗与字段匹配修复 · 2026-09-26

## 结论

同一份预先保存的 GPT 计划，现在能从 Google Flights 首页查询 2026 年 10 月 20 日苏黎世到伦敦、单程、1 位成人、经济舱，并显示真实航班结果。最终一轮 6.631 秒、11 次本地 Laya 调用；9 项独立检查全部通过，另人工核对截图。未选择或预订航班。

这是本项目的 Laya 执行测试，不是官方 TypeSafe Jev 服务的测试。GPT 计划来源于 Codex 对话；运行中没有请求 GPT API 或 Qwen。耗时不含计划生成、模型加载和首次页面导航，不能与官方包含文本生成的耗时作直接性能比较。

## 修复内容

- **允许拒绝错误字段。** 字段对要求的反向判断若更支持 none，分配器不会强行绑定；后续点击候选也不会重新引入刚被拒绝的控件。唯一且明确的完整字段名、完整词匹配或当前精确值可直接提供匹配证据，避免小模型把 Economy 匹配到 Return 日期。字段名匹配保留 from/to 等词，不用去停用词后的词干判断这类方向区别。
- **保存有效校验结果。** 原先“语义判断已满足”的字段会在下次刷新时被错误清除，导致重新处理人数。现在只在节点和值均不变时复用校验结果；值变化会重新检查。
- **日期确认是独立子步骤。** 快照记录控件所属弹窗。选中与要求相符的选项后，先点击同一弹窗内唯一的 Done/Confirm/Apply 控件，等待弹窗关闭，再处理外层表单。日历的 Done 不再被记作最终搜索提交；确认已执行后不会重复点击。
- **保留尚未完成的自动补全。** 在较慢加载的一轮中，输入机场后候选晚于首个快照出现，旧规则转去处理下一字段。现在等待期间保留原输入步骤，在候选出现后继续选择；有展开证据的 combobox 在候选未出现时有界等待，不重复输入。
- **修正并补强验收。** Google 把出发地控件标签扩展为 `Where from? Zürich ZRH`，值仍是 `Zürich`。独立检查允许标签附带机场信息，但继续要求正确的角色和实际值；另加入 1 位成人和经济舱检查。没有删除起点条件，也没有把 DONE 当成功。

这些是基于观察到的 DOM 信息的通用规则，没有给生产策略写入航线、日期、Google 选择器或预设点击序列。具备多个确认按钮、多个未完成字段的复杂弹窗、无语义标记的控件，以及错误规划仍需要进一步评估。
