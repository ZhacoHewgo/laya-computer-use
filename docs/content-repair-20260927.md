# 正文验证与修复条件保护 — 2026-09-27

## 复现

新增六项针对性测试，修改前五项失败、一项通过：订阅提示被当作正文；导航文字被当作正文；修复计划可以删除语言要求、改成另一种语言或弱化 finish。讨论订阅机制的正常文章作为正向对照。

## 修改

- 对阅读正文/摘要/全文的目标，从可见段落、引用块或 articleBody 读取内容，排除导航、表单、侧栏、页脚等。原先仅判断整个主区域长度的方式不再足够。
- 英文和中文的明确登录/订阅阅读指令会直接 BLOCKED，记录 stop_reason，不尝试登录、订阅或调用规划器绕过限制。
- 修复器收到最后接受的计划。非查询字段的值及目标条目不能被删除或改写；字段名可在值唯一对应时重新映射。搜索词可调整，但搜索类别等条件仍受保护。
- 保留初始 finish，以及累计接受的 authors / identity_terms。被拒绝的候选计划单独记录，原计划不被覆盖，执行器不使用被拒绝的计划。
- 拒绝也计入最多两次修复预算；用尽后停止并记录缺失或改变的条件。

## 适用边界

- 保护的是已接受计划中表达出来的条件；初始规划完全遗漏的自然语言要求仍需要独立检查。
- 保守比较可能拒绝语义相同但表达不同的日期或地点，且不能证明重新命名字段后的所有语义映射都正确。
- 明确要求登录/订阅时停止不是绕过权限；付费墙检测只有已实现的中英文模式，不保证识别全部样式或语言。
- 段落结构和长度只是必要证据，不能证明正文完整。页面只有非标准 div、被截断的内容或复杂遮罩时仍有局限。
- 本轮未处理配置文件解析、CI 和文档历史整理；未提交或推送本轮代码，8770 常驻服务未重启。
