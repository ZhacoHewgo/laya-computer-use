# 搜索结果等待与查找修复 · 2026-09-26

## 本次结论

同一份预先提供的 GPT 计划，修复前停在 Python 搜索页；修复后由本地 Laya 执行，打开了 Data Structures 章节。独立检查确认官方域名、章节路径、主标题及 `append` / `extend` 的正文说明，另人工复核最终截图。

这里的 GPT 计划来自 Codex 对话，作为保存的 JSON 输入；**程序没有调用 GPT API，也没有调用 Qwen**。Laya 负责候选选择，通用规则负责等待、滚动与操作组合。这不是已经接通自动 GPT 规划，也不是 Laya 单独理解并完成了全部任务。

## 问题与修复

1. **提交后的页面跳转不代表结果加载完毕。** 原策略停止后继续只读观察，约两秒后才出现搜索条目，约七秒后搜索结束。现在提交后给予条目加载最多五秒的观察宽限期；目标完整短语已经出现时可以提前选择，不必等满五秒。等待操作间隔由 0.1 秒改为 0.25 秒，避免短时间耗尽步骤预算。
2. **目标在下方，当前屏幕没有显示。** 宽限期结束仍未找到完整短语时，使用页面实际提供的向下滚动操作继续查找。最多八个不同滚动位置；位置未变化时不重复滚动。没有生成选择器或写入 Python 文档专用导航规则。
3. **搜索框滚出屏幕后错误等待。** 已完成的输入条件不再因为对应控件离开当前屏幕就触发填表等待。
4. **词干重合造成误选。** `struct … data` 与 `Data Structures` 在旧词干规则下相似。现在优先包含完整规范化短语的候选，在等待及滚动阶段不急于选择局部重合项。预算耗尽后仍保留原有模糊匹配，因此这不是所有错误点击的完整解决方案。
5. **旧验收代码依赖参数名。** 新版页面为 `list.append(value, /)`，旧检查器只认 `list.append(x)`。现在独立读取 More on Lists 节内的方法签名与解释；仅出现目录、标题或方法名称不能通过。

## 实测

各场景一次最终有界运行，每个最多 50 步。所有计划在执行前保存，执行中禁止文本模型调用。Python 使用与修复前完全相同的计划；其他场景是此次对话提供的计划，不应与先前 Qwen 端到端耗时直接比较。

Python 的 22 步包括：填搜索框、提交、16 次等待、3 次滚动、点击章节。不是 22 次点击。耗时包含此次循环的截图观察，排除模型加载、起始页面导航及 GPT 计划生成。等待主要用于异步加载；增加等待时间并不代表模型推理变慢。

Wikipedia 停留首页，未执行浏览器动作；这是搜索入口处理仍不足的表现。Flights 填写了部分条件后停在票型选项中，最终页检查全部不通过；不能将中间填写动作报告为航班搜索成功。两项失败均保留。

这些固定开发案例不是留出测试集，四项通过不能解释成通用任务成功率。五秒宽限和八次滚动仍可能漏掉更慢或更长的结果；模糊标题、跨语言描述、折叠搜索入口和复杂日期/票型控件需要后续工作。
