# 浏览器代理系统性修复（2026-09-26）

## 修改计划与落地

1. **观察信息**：规划器接收控件角色、当前值、下拉选项和页面上下文；保留真正的 Search 导航链接。
2. **计划约束**：拒绝重复字段，避免额外注入第二条搜索要求；导航只能引用观察到的入口；下拉选择加入拒绝项。
3. **有限纠错**：初次规划之后最多纠错两轮，每轮最多三次格式/计划校验尝试。保留原始目标、执行记录及各次规划响应，不自动重放浏览器操作。
4. **执行补全**：搜索表单缺少提交按钮时允许使用观察到的回车动作。页面内搜索完成后进入详情页，保留已满足的搜索条件，不把详情页搜索框当作未完成字段。
5. **完成检查**：检查目标身份、正文、标题及搜索结果上下文；带路径的目标排除其下级详情页；相似论文标题不再仅因包含目标短语而通过。

这些判断仍是启发式检查，不能证明任意自然语言任务都完成。独立的任务结果检查继续保留。

## 测试方法

实际 API：用户提供的本地兼容入口，请求模型 `cx/gpt-6-luna`，响应模型 `gpt-6-luna`。Laya 使用本机缓存的 multilingual 权重。密钥仅通过隐藏输入传入进程，未写入报告或源码。

每个真实任务最多 40 次 tick、90 秒循环预算（同步请求可能使墙钟时间超过预算）。不通过人工操作替模型完成任务；独立读取最终 URL、标题、作者和正文证据。

迭代中遇到过浏览器读取超时、错误完成判断和错误论文，原记录保留在 artifacts/repair-*，没有只保留成功尝试。最终结果见下表。

图书测试原本只接受 /ebooks/1342；用户没有指定版本，因此修订为数字图书详情页路径，加正确书名、作者、在线阅读与 EPUB 证据。/ebooks/42671 的页面截图已人工核验，确属 Jane Austen 的 Pride and Prejudice。

## 尚存限制

- 搜索结果链接可能只标编号，相关标题在相邻文字中；目前候选项关联上下文仍不足，arXiv 容易选中衍生论文。
- GPT 输出、动态渲染和网络存在波动；同一任务的耗时与步骤数不稳定。
- 更丰富上下文和纠错会增加 API token 与调用次数；本地网关不等于后端免费或本地推理。
- 完成检查不应被当作通用成功率。离线单测数量也不等于真实网站成功率。

## 下一阶段
