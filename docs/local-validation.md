## 本次发现并修正的问题

- 小型规划模型会把“搜索车次”或“View Casa Flora”按钮当作字段或目标。限制提供给规划器的内容为表单字段，并增加搜索与打开条目的区分说明后，本地案例通过。提示改进不保证消除其它任务上的规划错误。
- 未满足的字段用完尝试次数后会停止，不能被计为已完成。
- 同页结果必须有提交后出现的新文本；原有页面文字和单独的模型完成判断不能作为结果证据。
- 点到包含常见词的导航项，不再仅凭该词推断目标文章/条目已经打开。
- 规则选择的概率为空；模型调用次数独立记录。中文案例只用了两次 Laya 调用：搜索按钮选择、页面类型判断。其余填表工作大多由已知字段名和程序规则完成。
- 中文测试页对插入页面的字段值做 HTML 转义。启动器隔离浏览器配置、使用本地规划服务和缓存权重。

第一轮中文案例填好了五项条件、点击了搜索，但错误的目标规划使流程停止；第一轮酒店案例曾显示 DONE，却没有提交城市筛选。独立检查发现了这两个问题，失败轨迹保存在本机 `artifacts/verification/`，未把浏览器配置或运行缓存上传到仓库。

## 可复现检查

先启动本地演示，再在另一个终端运行：

```bash
uv run --extra local python -m examples.evaluate_local
# 可选：同时观察真实网站的限制；当前配置的失败会返回非零退出码
uv run --extra local python -m examples.evaluate_local --scenarios zh travel research wikipedia flights
```

默认使用 8770 / 8771 / 9334 端口。更换端口时需相应设置评估环境；外部页面结果可能随网络、页面版本、地区和自动化限制变化。`DONE` 与独立验证结果分别记录，二者均通过才算测试成功。

开发检查：68 项离线测试通过；Ruff、JavaScript 语法检查、源码和 wheel 构建通过。离线单元测试中的模型是替身，上表另行使用真实本地模型运行。

这仍是受限的 DOM 浏览器原型：它不读取截图理解页面，不控制任意桌面应用；通用网页任务、日期控件、动态菜单和小模型的规划准确性仍需继续验证。
